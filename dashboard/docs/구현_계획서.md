# FlatWay 보행 안전 대시보드 웹 애플리케이션 개발 계획 (아키텍처 반영본)

사용자께서 추가하신 아키텍처 다이어그램을 반영하여, **Next.js 시각화 대시보드**와 **Supabase 데이터베이스**를 연동하는 구조로 계획을 수정하여 개발을 진행합니다.

```
[Flutter 모바일 앱] (측정)
       │
       ▼
 [Supabase 데이터베이스] (데이터 저장)
       │
       ▼
 [Next.js 대시보드] (지도 시각화) ◀── (현단계 구현 대상)
       │
       ▼
[Flutter 모바일 앱] (안내)
```

---

## 1. 개요 및 요구사항
* **웹 대시보드 목적:** Supabase에 저장된 노면 정보(단차, 파손) 및 건물 편의 정보를 가져와 지도로 시각화하고 실시간 제보를 시뮬레이션함.
* **주요 기술 스택:**
  - **Framework:** Next.js (App Router 활용)
  - **Database:** Supabase (SQL 및 실시간 데이터 처리)
  - **Map Library:** Leaflet / React-Leaflet (Next.js SSR 비활성화 dynamic import 사용)
  - **Styling:** Vanilla CSS
* **주요 기능:**
  1. **Supabase 실시간 동기화:** Supabase DB의 단차/파손/경사로 데이터를 조회하여 지도 위에 마커로 시각화.
  2. **실시간 제보 등록:** 지도 클릭 시 제보 등록 폼을 통해 Supabase 테이블에 직접 `INSERT` 수행하여 실시간 반영.
  3. **안전 지표 대시보드:** 총 제보 수, 미해결 단차 건수, 건물 경사로 설치 비율 등을 카드로 노출.

## 2. 사용자 검토 필요 사항
> [!IMPORTANT]
> **Next.js & Leaflet SSR 호환성**
> - Leaflet은 브라우저 환경 객체(`window`)를 직접 참조하므로, Next.js의 서버 사이드 렌더링(SSR) 과정에서 오류가 발생할 수 있습니다.
> - 따라서 지도 컴포넌트는 `next/dynamic`을 사용하여 `ssr: false` 옵션으로 클라이언트 사이드에서만 렌더링되도록 구현합니다.
>
> **Supabase 연결 설정**
> - 프로젝트 루트에 `.env.local` 파일을 생성하여 `NEXT_PUBLIC_SUPABASE_URL` 및 `NEXT_PUBLIC_SUPABASE_ANON_KEY`를 환경 변수로 관리합니다.
> - 로컬 개발 확인용 테스트 프로젝트를 Supabase에 구성하거나, 기존 프로젝트를 연동합니다.

### 3.2 데이터베이스 스키마 정의 (Supabase SQL)
Supabase에 테이블을 생성하기 위한 SQL 스키마를 구성합니다.

```sql
-- 1. 노면 위험 정보 테이블
CREATE TABLE hazards (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  type VARCHAR(50) NOT NULL, -- step, damage, obstacle, slope
  latitude DOUBLE PRECISION NOT NULL,
  longitude DOUBLE PRECISION NOT NULL,
  step_height_cm NUMERIC,
  severity VARCHAR(20) NOT NULL, -- high, medium, low
  description TEXT,
  image_url TEXT,
  reported_at TIMESTAMP WITH TIME ZONE DEFAULT timezone('utc'::text, now()) NOT NULL,
  is_verified BOOLEAN DEFAULT false NOT NULL
);

-- 2. 건물 접근성 정보 테이블
CREATE TABLE buildings (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  name VARCHAR(100) NOT NULL,
  latitude DOUBLE PRECISION NOT NULL,
  longitude DOUBLE PRECISION NOT NULL,
  has_ramp BOOLEAN DEFAULT false NOT NULL,
  ramp_slope_degree NUMERIC,
  has_elevator BOOLEAN DEFAULT false NOT NULL,
  main_entrance_type VARCHAR(50) DEFAULT 'manual' NOT NULL, -- automatic, manual, revolving
  disabled_toilet BOOLEAN DEFAULT false NOT NULL,
  image_url TEXT,
  updated_at TIMESTAMP WITH TIME ZONE DEFAULT timezone('utc'::text, now()) NOT NULL
);
```

## 4. 검증 계획

### 4.1 수동 검증 및 시뮬레이션
1. **Supabase 연동 확인:** 대시보드 시작 시 Supabase에서 샘플 데이터(인천 작전역 및 작전여고 부근)가 성공적으로 패치되는지 네트워크 로그 분석.
2. **지도 컴포넌트 로딩 검증:** SSR 오류 없이 지도가 화면에 정상 렌더링되는지 브라우저 콘솔 로그 확인.
3. **제보 등록 시뮬레이션 테스트:**
   - 대시보드에서 지도상의 빈 공간 클릭 -> 제보 모달 팝업 -> 데이터 입력 후 저장.
   - Supabase 콘솔(또는 MCP 도구)을 통해 테이블에 데이터가 정상적으로 `INSERT` 되었는지 검증.
   - 새로운 핀이 지도상에 표시되고 통계 카드의 제보 수 카운트가 올라가는지 확인.
