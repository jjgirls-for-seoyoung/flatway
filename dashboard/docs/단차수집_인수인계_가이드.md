# ♿ FlatWay 통합 데이터 수집 및 연산 인수인계 가이드

본 문서는 **FlatWay** 프로젝트에서 보행 약자(휠체어, 유모차 사용자 등)에게 최적화된 **도어 투 도어(Door-to-Door) 안전 경로**를 안내하기 위해 필요한 모든 데이터의 규격, 수집 방법, 연산 알고리즘(센서 기반 단차 추출) 및 보안 검증 체계를 통합하여 설명하는 인수인계 가이드라인입니다.

## 3. 센서 기반 보도 단차 높이 연산 알고리즘

모바일 앱이 100Hz 주파수로 보행 데이터를 수집해 전송한 가속도 크기($|a|$) 변화 분석을 통해 실제 보도블록 턱(단차)의 높이를 구하는 방법입니다.

### 3.1 물리적 모델 및 필터링 공식
진동이나 단차 충격은 Z축 가속도뿐만 아니라 디바이스의 흔들림 각도에 영향을 받으므로 아래 단계를 통해 충격 성분만 가공합니다.

#### 1) 3축 가속도 크기 (Magnitude) 산출
중력 보정을 위해 벡터 합 크기를 구합니다.
\[|a| = \sqrt{a_x^2 + a_y^2 + a_z^2}\]

#### 2) 고주파 통과 필터 (High-Pass Filter)
걷거나 휠체어가 정속 주행할 때 발생하는 저주파 성분을 지우고 턱을 타고 넘을 때의 순간적 덜컹거림(고주파)만 분리합니다.
\[y_t = \alpha \cdot (y_{t-1} + x_t - x_{t-1}) \quad (\alpha \approx 0.85)\]

#### 3) 단차 높이 ($Height$) 추정 공식
\[Height(cm) = \beta \times (Peak\_a - Base\_a) + \gamma\]
* **$Peak\_a$**: 하이패스 필터를 통과한 충격 파형의 로컬 최대값
* **$Base\_a$**: 노면 상태에 따른 평균적인 베이스라인 진동 (충격 전 0.5초 평균)
* **$\beta$ (비례 상수)**: 약 `1.5 ~ 2.0` (디바이스 거치 상태와 기종에 맞추어 보정)
* **$\gamma$ (기본 오차 보정치)**: 약 `0.5`

### 3.2 단차 분석 자바스크립트 소스 코드
```javascript
/**
 * 100Hz 가속도 청크 데이터를 스캔하여 단차(Step) 요소를 추출합니다.
 * @param {Array} records - 센서 로그 배열 (시간, 위경도, 3축 가속도 포함)
 * @returns {Array} 추출된 단차(Step) 데이터 목록
 */
export function extractStepsFromSensorChunks(records) {
  const detectedSteps = [];
  const HPF_ALPHA = 0.85;       // 하이패스 필터 차단 가중치
  const IMPULSE_LIMIT = 3.8;    // 단차 판단 최소 충격 임계값 (m/s²)
  const CONVERSION_FACTOR = 1.8;// 가속도 -> cm 변환 비례 상수

  let prevRaw = 9.81;
  let prevFiltered = 0;

  for (let i = 1; i < records.length - 1; i++) {
    const rawVal = records[i].accel_magnitude;

    // 1. 하이패스 필터 적용 (중력 및 이동 관성 제거)
    const filteredVal = HPF_ALPHA * (prevFiltered + rawVal - prevRaw);
    prevRaw = rawVal;
    prevFiltered = filteredVal;

    const absFilter = Math.abs(filteredVal);

    // 2. 피크 검출 (주변 프레임보다 크고 임계치를 넘는 순간)
    if (absFilter > IMPULSE_LIMIT) {
      const nextRaw = records[i + 1].accel_magnitude;
      const nextFiltered = HPF_ALPHA * (filteredVal + nextRaw - rawVal);

      if (absFilter > Math.abs(prevFiltered) && absFilter > Math.abs(nextFiltered)) {
        // 3. 단차 높이 cm 역추정
        const stepHeight = parseFloat((absFilter * CONVERSION_FACTOR).toFixed(1));
        
        if (stepHeight >= 1.0) {
          detectedSteps.push({
            type: 'step',
            latitude: records[i].latitude,
            longitude: records[i].longitude,
            step_height_cm: stepHeight,
            severity: stepHeight >= 5.0 ? 'high' : stepHeight >= 2.0 ? 'medium' : 'low',
            reported_at: records[i].timestamp,
            description: `[자동 센서 분석] Z축 충격 누적으로 추정된 ${stepHeight}cm 단차`
          });
          
          // 연속 중복 방지를 위해 감지 시점 기준 1초 분량(100프레임) 스킵
          i += 100;
        }
      }
    }
  }
  return detectedSteps;
}
```

## 4. 실내외 연속 '도어 투 도어(Door-to-Door)' 매핑 기법

실외 보행 안내 경로와 건물 내 편의시설 정보의 파편화 문제를 해결하기 위해 **진입점 노드(Transition Node)**를 구조화하여 통합합니다.

### 4.1 연결 원리 (Transition Mapping)
1. **실외 노드망 연장:** 도로의 가장 가까운 보도 노드에서 시작하여 건물의 실제 경사로가 위치한 좌표인 **'주출입구 진입점(Entry Node)'**으로 실외 경로선을 연장합니다.
2. **실내 전이 노드 생성:** 진입점에 도달하면 건물 구조 데이터(`buildings` 테이블의 `indoor_path` 컬럼)를 기반으로 **'주출입구 $\rightarrow$ 승강기(Elevator) $\rightarrow$ 목적지 호수'**로 연결되는 실내 연장선(지도 상 점선)으로 시각화 경로를 이어줍니다.
3. **접근성 필터 연동:** 건물의 주출입문 타입이 회전문(`revolving`)이거나 수동문(`manual`)이고, 휠체어 사용자가 혼자 진입할 수 없는 경우, 실외 길찾기 경로 단계에서 해당 건물 진입을 원천 배제하거나 보조 진입로(장애인 전용 입구)로 강제 회전시킵니다.

```
[인도 도로 노드] ──────▶ [건물 주출입구 진입점(has_ramp 체크)] ┄┄(실내 점선)┄┄▶ [내부 엘리베이터]
```

## 6. 보안 및 정보 신뢰성 대책 (어뷰징 차단)

사용자가 장난으로 단차나 장애물을 가짜 제보하거나 센서 노이즈가 단차로 잘못 등록되는 것을 막기 위한 신뢰 등급(Trust Level) 시스템입니다.

### 6.1 신뢰 점수(Trust Score) 연산 로직
특정 위치에 새 제보(턱 감지 등)가 유입되면 백엔드는 **반경 20m 이내**에 누적된 데이터들을 모아 신뢰도를 다음과 같이 판별합니다.

\[Trust\_Score (\%) = \text{Min}\left(100, \left(S_{match} \times 20\right) + \left(U_{agree} \times 10\right) + \text{Photo\_Bonus}\right)\]

* **$S_{match}$ (센서 일치 횟수):** 제보 좌표 반경 20m 이내를 지나간 다른 다수의 모바일 디바이스 가속도 센서에서 덜컹거림(피크 검출)이 동시에 발생하여 누적된 횟수 (1건당 +20점)
* **$U_{agree}$ (사용자 동의 수):** 타인이 모바일 앱에서 "여기에 턱이 실제로 있습니다"라고 승인한 횟수 (1건당 +10점)
* **$\text{Photo\_Bonus}$ (사진 가점):** 제보자가 상세 설명과 함께 현장 사진을 직접 업로드한 신뢰성 높은 제보인 경우 (+30점)

### 6.2 신뢰도 등급 기준 및 처리 프로세스
1. **검증 대기 (`Trust_Score < 50%`):** 
   - 지도에 **노란색 반투명한 핀**으로 표시.
   - 신뢰성이 아직 보장되지 않아 실시간 대시보드 점수 계산 및 다른 사용자의 실제 경로 우회 추천 계산에 산입되지 않음.
2. **검증 완료 (`Trust_Score >= 50%`):**
   - 지도 상에 **선명한 빨간색(단차) 핀**으로 갱신.
   - 해당 구역의 보행 종합 안전 점수를 감점하고, 실시간 길찾기 중 해당 지점을 지날 때 턱 우회 알고리즘(2cm 한계 필터 등)에 완벽 반영됨.
