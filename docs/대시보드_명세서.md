# 🖥️ FlatWay 대시보드 개발 명세서

본 문서는 **FlatWay** 프로젝트에서 모바일 앱(Flutter)과 연동되어 보행 안전 데이터를 시각화하고 실시간 제보를 관리하는 **웹 대시보드(Next.js) 개발 파트**의 명세서 및 정리 문서입니다. 

팀원 및 평가자에게 본인이 담당한 대시보드 영역의 구현 범위와 기술 명세를 공유하기 위해 작성되었습니다.

---

## 1. 프로젝트 내 역할 및 개요
전체 아키텍처 중 **[Next.js 시각화 대시보드]** 파트를 전담 개발하였습니다.

```
[모바일 앱 (Flutter)] ──(측정 데이터 적재)──▶ [Supabase DB]
                                                   │
                                             (실시간 데이터 조회)
                                                   ▼
                                         [Next.js 대시보드 웹] (본인 담당)
```

* **주요 역할:** Flutter 앱이 GPS 및 센서로 측정해 Supabase DB에 적재한 도로 단차/파손 정보와 건물 접근성 데이터를 웹 지도 상에 실시간으로 시각화하고, 웹 사용자가 직접 위험 지역을 제보하는 크라우드소싱 시뮬레이터를 제공함.

---

## 2. 기술 스택 (Tech Stack)
* **Framework:** Next.js 16 (App Router, Client-side Hydration)
* **Library:**
  - **지도 라이브러리:** Leaflet & React-Leaflet (OpenStreetMap)
  - **백엔드/DB 연동:** @supabase/supabase-js
  - **아이콘:** Lucide React
* **Styling:** Vanilla CSS (CSS Variables, Glassmorphism, Responsive Grid)

---

## 3. 데이터베이스 연동 명세 (Supabase)
모바일 앱(Flutter)과 데이터를 공유하기 위해 Supabase 상에 다음 두 개의 테이블을 연동 및 설계하였습니다.

### 3.1 노면 위험 정보 테이블 (`hazards`)
Flutter 앱의 센서 데이터 또는 웹 대시보드의 제보 데이터를 저장합니다.

| 컬럼명 | 데이터 타입 | 설명 |
| :--- | :--- | :--- |
| `id` | UUID (PK) | 고유 식별자 (자동 생성) |
| `type` | VARCHAR | 위험 유형 (`step`: 단차, `damage`: 파손, `obstacle`: 적치물, `slope`: 급경사) |
| `latitude` | DOUBLE PRECISION | 위도 (GPS) |
| `longitude` | DOUBLE PRECISION | 경도 (GPS) |
| `step_height_cm` | NUMERIC | 단차 높이 (단차 유형일 때만 기재, cm) |
| `severity` | VARCHAR | 심각도 (`high`: 우회 필수, `medium`: 보조 필요, `low`: 경미) |
| `description` | TEXT | 상세 상황 및 제보 내용 설명 |
| `reported_at` | TIMESTAMP | 제보 및 등록 일시 (기본값 현재시각) |
| `is_verified` | BOOLEAN | 관리자 검증 완료 여부 (기본값 `false`) |

### 3.2 건물 접근성 정보 테이블 (`buildings`)
건물 입구의 장애인 시설 상태를 저장합니다.

| 컬럼명 | 데이터 타입 | 설명 |
| :--- | :--- | :--- |
| `id` | UUID (PK) | 고유 식별자 |
| `name` | VARCHAR | 건물 명칭 (예: 작전역 4번 출구, 작전여고 등) |
| `latitude` | DOUBLE PRECISION | 위도 (GPS) |
| `longitude` | DOUBLE PRECISION | 경도 (GPS) |
| `has_ramp` | BOOLEAN | 진입로 경사로 설치 여부 (Y/N) |
| `ramp_slope_degree`| NUMERIC | 경사로 각도 (도, °) |
| `has_elevator` | BOOLEAN | 장애인용 엘리베이터 유무 (Y/N) |
| `main_entrance_type`| VARCHAR | 출입구 개폐 방식 (`automatic`: 자동문, `manual`: 여닫이 등) |
| `disabled_toilet` | BOOLEAN | 장애인 화장실 설치 여부 (Y/N) |

## 4. 핵심 기능 구현 세부사항

### 4.1 지능형 Supabase 폴백 시스템 (`supabaseClient.js`)
* **설명:** Supabase 연결 API Key가 비어있거나 플레이스홀더 상태일 경우, 에러로 웹이 멈추는 대신 **로컬 저장소(localStorage) 모드**로 자동 전환됩니다. 
* **의의:** 외부 연결 환경이나 API 점검 시에도 대시보드가 로컬 목 데이터를 활용해 100% 정상 작동하므로 시연 및 로컬 테스트가 원활합니다.

### 4.2 Next.js & Leaflet SSR 예외 처리 (`DynamicMap.js`)
* **설명:** Leaflet 지도 라이브러리는 브라우저의 `window` 객체에 의존하므로 서버사이드 렌더링 시 빌드 에러를 유발합니다. 
* **해결:** `next/dynamic`을 통해 `ssr: false` 설정으로 지도를 dynamic import 함으로써 빌드 안정성을 확보했습니다.

### 4.3 휠체어 유형별 우회 경로 표시
* **설명:** 지도 상에 일반 보행 경로 외에도 **[전동 휠체어 추천 경로]**, **[수동 휠체어 추천 경로]** 선(Polyline)을 다르게 시각화합니다.
* **우회 기준:** 
  - **전동 휠체어:** 단차가 2cm 이상인 높은 보도 턱과 깨진 노면을 우회.
  - **수동 휠체어:** 단차/파손 뿐 아니라 오르막 경사(급경사) 구간까지 추가로 고려하여 최저 경사 도로로 우회.

### 4.4 크라우드소싱 제보 등록 시뮬레이터 (`ReportModal.js`)
* **설명:** 지도 상의 임의의 보행로를 클릭하면 클릭된 좌표가 자동 바인딩되어 제보 모달 폼이 나타납니다.
* **실시간 통계 연동:** 제보 등록 완료 시 Supabase(또는 로컬 스토리지)에 바로 반영되어 지도의 핀 마커가 생성되고, 왼쪽 대시보드의 **'보행 안전 종합 점수'가 실시간으로 하락 감점 계산**됩니다.

## 5. 대시보드 실행 및 배포 방법
1. **의존성 패키지 설치:**
   ```bash
   npm install
   ```
2. **로컬 실행:**
   ```bash
   npm run dev
   ```
3. **빌드 검증:**
   ```bash
   npm run build
   ```
